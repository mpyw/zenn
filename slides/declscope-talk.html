What declscope guards

declscope が守るのは、2 種類の境界

boundary

この file から、あの宣言に
触ってよいか？

orderRepository
  → normalizeEmail
     in userRepository
既定で ON

qualify

シンボルに namespace を含めて
識別性を確保しているか？

scan       → 誰の？
scanUser   → user のもの
既定は OFF・ON 推奨

boundary は利用関係、qualify は名前と置き場所を検査する。

01

scope は 2 種類

private自分の namespace
packagepackage 内のどこでも

Boundary rule

boundary 違反への答えは、必ず 2 つ

A

境界を守る

使用箇所や宣言を同一 namespace に移す。

move usagemove declaration
OR
B

共有を宣言する

//declscope:package
func normalizeEmail(s string) string

email.go に移し、共有物だという判断をソースへ残す

Shared namespace

複数 file で 1 つの関心なら、束ねられる

//declscope:namespace statement

package database

func (s *Statement) Where(...) { ... }
type Statementwheres []stringargs []any
func (*Statement)Where(...)

物理 file を出発点にしつつ、実際の関心範囲へ合わせられる。

Qualify rule

qualify は「名前を長くしろ」ではない

scanUser → userRepositoryScanUser

機械提案どおり rename？

自動修正提案では namespace がプレフィクスになる。でも、名前が不自然。

namespace のほうを見直す

//declscope:namespace user

scanUser が自然に収まる。

問われているのは、その名前と置き場所が噛み合っているか
