# はじめに

**AI が書いた文章を，人間が一文字ずつ手で打ち写す。**

字面だけ見ると何かの罰ゲームですが，タイピングの練習としては案外まともです。だって我々が普段 AI に書かせているコードって，自分では一文字も打っていないわけですから。たまには手を動かしましょう。

というわけで作りました。

https://mpyw.me/you-are-llm/

https://github.com/mpyw/you-are-llm

![You are LLM](https://raw.githubusercontent.com/mpyw/you-are-llm/main/docs/screen-intro.png)

ルールは単純です。コーディングセッションの **アシスタント側の発言を，補完なしで全部打つ**。それだけ。ユーザー側の発言は「お題」なので打たなくていいです。

以下，こだわったところを並べていきます。技術的な話はほぼしません。

# こだわり 1 : アシスタントの喋り方が AI 臭い

これが本命です。

素材を作るとき，最初は普通に丁寧な技術解説を書かせていました。読み返してみると，正しいんだけど面白くない。**「これ，AI が書いたな」と一目で分かる文章じゃないと，このゲームは成立しない**のです。

ということで，AI 特有の言い回しを大量に仕込みました。分類するとこんな感じです。

| 系統 | 例 |
|:---|:---|
| 翻訳が途中で力尽きたやつ | `Now、` `Let's` `Here's` `Note:` |
| 頼んでもいない称賛 | `鋭いご指摘です` `素晴らしい質問です` `承知しました` |
| 辞書を経由してしか出てこない語 | **`正本`** `堅牢` `優雅に` `べき等` `関心の分離` `銀の弾丸` |
| 文章の家具 | `〜という点に注意することが重要です` `〜を保証します` `言い換えると` |

個人的に一番好きなのは **「正本」** です。 source of truth の訳語としてたまに出てくるんですが，日常会話で「正本」と言う人を私は見たことがありません。

そして **「Now、」**。 "Now, let's ..." の "Now" が「では」に訳されないまま残っているやつ。これが文頭に来ると，もう完全に AI です。

# こだわり 2 : 「実装しました！」→「実装できていませんでした」

さらに外せないのが，**自己訂正のパターン**です。

やったと言い切った次のターンで「やっていませんでした」と戻ってくる，アレ。あるいは自信満々に説明しておいて，指摘されたら手のひらを返すアレ。心当たりがない人はいないと思います。

実際に仕込んだ例を挙げます。 Rust のライフタイム地獄回から。

> **1 ターン目**
> `get_or_insert` を実装しました！先に `get` で覗いて，無ければ `compute` した結果を `insert` して，もう一度引いた参照を返します。**ベストプラクティスに沿った素直な実装です。**

ユーザーが `cargo check` を通すと `E0502` が出ます。

> **2 ターン目**
> **改めて確認したところ，先ほどの実装は借用チェッカを通っていませんでした。申し訳ありません。**

完璧ですね。

Java 回では「削除したと述べましたが，実際には残っていました」，C++ 回では「ビルドが通ると述べましたが，実際には include を落としていました」と言わせています。 Go 回に至っては，撤回を成立させるために **わざわざ前のブロックに「これで全ての経路が確実に停止します」という断言を追加** してから引っくり返させました。芸が細かい。

ちなみにこの「AI 臭さ」，**機械的にチェックしています**。日本語セッションには難易度に応じて 3〜5 種類の言い回しが必須で，さらに Normal 以上には自己訂正の語が必須。足りないとテストが落ちます。

:::message
なお「濃くしろ」と指示しすぎると全ブロックの頭が「素晴らしい質問です！」になって 2 個目で笑えなくなるので，**1 セッションにつき 1 ブロックは素のまま残す**ルールにしています。振りかけるのであって，漬け込むのではない。
:::

# こだわり 3 : 要件が二転三転して `sed` を打たされる

現場のリアルを再現するうえで外せないのが，**後出しの要件変更**です。

Normal 以上のセッションでは，一度書いたコードに対してユーザーが「やっぱり 5 回にして」「上限つけて」と言い出します。そしてアシスタントは，全文を書き直す代わりに `sed` で当てにいきます。

```
sed -i '' -e 's/`on${Capitalize<string & K>}`/`handle${Capitalize<K \& string>}`/' -e "s/Listeners\['onSave'\]/Listeners['handleSave']/" src/events/emitter.ts
```

**置換側の `&` をバックスラッシュで逃がす回**です。打鍵教材としては最高に嫌がらせですね。バッククォートとテンプレートリテラルも入っています。

`sed` はどれも実際に当ててみて動作確認済みなので，**打ち終わったあと本当に使えます**。使う機会があるかは知りません。

# こだわり 4 : 題材が地味に嫌なところを突いてくる

全 48 セッション，8 言語 × 3 難易度 × 日英で作りました。題材はこんな感じです。

| 言語 | Hard の題材 |
|:---|:---|
| Java | Getter と Setter を増やし続けた先に `record` がある |
| Rust | `get_or_insert` のライフタイムで往復する |
| C | パディングと `sizeof` の取り違えを潰す |
| C# | null 許容参照型の警告を潰す |
| PHP | `md5` のパスワードを `password_hash` に寄せる |

Java 回が我ながら性格が悪くて，**フィールドが増えるたびに Getter と Setter を手で書かされ**，書き忘れを指摘されて直し，最後にユーザーが「やっぱり全部 record にして」と言い出して**全部消える**という構成です。タイピング量だけはしっかり稼げます。

# こだわり 5 : 「考え中」の演出

打鍵中，アシスタント側には **スピナーと，シマーのかかった文言** が出ます。コーディングエージェントが作業中に出しているアレのオマージュです。ブランド名やロゴには一切寄せていませんが，雰囲気は伝わると思います。

文言は 2.6 秒ごとに入れ替わります。

```
Thinking / Deliberating / Weighing the tradeoffs
Consulting the source of truth / Rereading the prompt
Second guessing itself / Drafting a retraction / Checking that again
```

**`Consulting the source of truth`（正本を確認中）** と **`Drafting a retraction`（撤回文を作成中）** は，こだわり 1 と 2 を踏んだ内輪ネタです。

# こだわり 6 : ランク名

クリアすると S 〜 D でランクが付きます。速度だけでは取れず，各段に正確率の下限があります。

| ランク | 評 |
|:---:|:---|
| **S** | Nothing to correct |
| **A** | Ship it |
| **B** | Works on my machine |
| **C** | Needs another pass |
| **D** | Rolled back |

D の `Rolled back` を出したときの気持ちを味わってほしい。

# 地味に大事だった話

ひとつだけ実装上の話をします。

日本語セッションでは，**漢字ではなく読み仮名の方を打たせています**。当たり前に思えますが，これは避けられません。 IME は「かな → 漢字」の向きに変換するので，ローマ字入力から漢字に到達する経路が存在しないからです。

なので素材の日本語には，表示用の本文とは別に**漢字ゼロの読み**が必ず付いています。「正本」なら「せいほん」，「銀の弾丸」なら「ぎんのだんがん」。ここを 1 文字でも間違えると **物理的にクリア不可能なステージ**が誕生するので，全セッションの全ステップを実際にエンジンに通して打ち切れることをテストしています。

ローマ字の揺れも一通り許容しています。「し」は `si` でも `shi` でも `ci` でも通るし，「きゃ」は `kya` でも `kixya` でも通ります。「ん」を `n` 一文字で済ませられるかどうかが後続の文字で変わる，みたいな IME の細かい挙動も再現しました。

:::message
AZIK 対応の要望を友人からもらっているのですが，打鍵表の裏を取れていないので未対応です。差し替えられる構造にはしてあります。
:::
